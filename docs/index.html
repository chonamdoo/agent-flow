agent-flow

An agent’s self-report is not evidence. “I wrote the tests” proves nothing, so the runner reads the command log the hooks recorded and judges for itself.

Install

brew tap chonamdoo/agent-flow https://github.com/chonamdoo/agent-flow
brew install chonamdoo/agent-flow/agent-flow
agent-flow .

The tap takes an explicit URL because this repository is not named homebrew-*. Install by the fully qualified name: since Homebrew 6.0 a third-party tap needs explicit trust, and the qualified name grants it for this one formula. The third line installs the workflow into the project in the current directory; a bare path is the install command, so agent-flow <dir> works without changing directory. Run it once per project, not once per session.

What it verifies

  • Routing authority sits with the runner. Workflow YAML only defines the phases. The runner decides which phase comes next and prints the next_command, so an agent cannot skip a phase on its own.
  • Completion gate markers. A phase that declares required markers advances only when every one of them is answered in the ## Completion Gate block of its artifact. Marker values are cross-checked against the body, so a count in place of a list is rejected.
  • Observation over claims. A PostToolUse hook records every command that ran. The runner reads that log, so a red phase with no test command in it fails no matter what the artifact claims.
  • One verification method per requirement. In the workflows that carry a SPEC ledger, each numbered requirement declares test:, symbol:, or manual. The phase does not complete while an item is unmet, even after the reviewers approve.
  • Two independent reviewers. Review phases split the work across two or more sub-agent processes. A single request-changes decides the verdict, and the session that wrote the code cannot review in place of a failed reviewer.
  • Protected-branch and worktree isolation. Work happens in an isolated git worktree, a branch alone is not enough. A hook blocks commits and pushes on protected branches, a tripwire reports drift in the leader checkout, and a separate phase asks the user to approve the merge directly.
