# 프로그램 v3: 헤드룸 과제에서 판정만 고정한 arm을 잰다 (사이클 3, 2026-10-24 사전등록)

근거:
- 적대적 리뷰 2건(Claude, Codex). 요약은 #409 코멘트 6388150753, #417 코멘트 6388151767에 있다.
- v0·v1 파일럿(HANDOFF "2026-10-24 파일럿 결과")

이 문서는 run을 시작하기 전에 커밋한다. run을 시작한 뒤에는 규칙을 바꾸지 않는다. 바꿔야 하면 새 판을 만들고, 그 뒤의 수치는 탐색으로만 적는다.

## 질문

- **Q-V:** 절차를 강제하지 않고 판정만 고정하면, 맨 모델의 거짓 완료와 성공률이 나아지는가? 비용은 얼마나 드는가?
- **Q-B:** 고정 workflow(B, `development`)는 판정만 고정한 arm(V)보다 나은가?

## 과제

`lumi-web-v1`(비공개 평가기, 동결 지문은 run 전에 이 절에 덧붙인다). 고른 이유는 A 파일럿 1/3이고 거짓 완료가 2/3이기 때문이다.

## arm

| arm | 구성 |
|---|---|
| A | 맨 모델. 과제 문장과 완료 선언 규칙만 준다 |
| PS | A에 pstack 원칙 CLAUDE.md(`ps-v1`)를 더한다 |
| **V** | A와 같은 프롬프트, phase 없음. 대신 Stop hook으로 판정을 고정한다. ① 검증 명령이 통과해야 멈출 수 있다(실패 시 최대 3회 차단). ② 그다음 독립 리뷰어 1회: 별도 `claude -p`, 같은 모델, 읽기 전용, 과제 문서 대비 미충족 요구만 보고하고, 지적이 있으면 1회 차단한다. 리뷰어 비용은 run 비용에 더한다 |
| B | `development` workflow. 리뷰어와 phase는 kit 기본값이다 |

- 모든 arm은 같은 모델(Claude Opus 5.5)과 같은 CLI 버전을 쓴다.
- 제한은 2시간, $30이다(V는 리뷰어 포함).

## 표본과 순서

- arm마다 n=3이고 모두 12 run이다. 순서는 seed 20261025로 섞어 `order.txt`에 기록하고, 한 번에 하나씩 돌린다.
- 이 사이클은 n=3이라 **탐색**이다. 결론은 "신호"로만 적는다. 확정 비교는 효과 크기를 보고 n을 정해 다음 사이클에서 한다.
- harness 오류로 끊긴 run은 분모에서 빼고 같은 순서 자리에서 다시 돌린다. 사유는 `score --harness-error`로 남긴다.

## 지표 (모두 사전 정의)

1. **S** (성공): 평가기 S=1 ∧ complete 선언 ∧ 규칙 위반 없음 ∧ run_status ok.
2. **선언 정확도 2×2:**
   - 거짓 완료: complete ∧ S=0
   - 거짓 차단: blocked ∧ S=1
   - 무선언: 따로 센다
3. **G** (검사 통과율): 연속 지표라 n이 작을 때 보조로 본다.
4. **성공 1건당 비용** (실패 run 비용 포함)과 run 비용·시간 중앙값. 잡음 바닥은 v1 A 파일럿 3회의 범위로 둔다.
5. UI 유사도(탐색): `ui_similarity.py` 평균 changed_pixel_ratio. 판정에 쓰지 않는다.

## 판정 규칙 (채택 규칙 v3)

v2의 "비열등 ∧ 비용 우월" 규칙만으로는 "비싸지만 더 낫다"를 받을 수 없다. 그래서 목적별로 둘로 나눈다.

- **기본 arm 후보(품질 목적):** 다음을 모두 만족하면 그 arm을 "A보다 나은 신호"로 기록한다.
  - S 합계가 A보다 크다.
  - 거짓 완료 수가 A보다 적다.
  - 무결성 위반이 0이다.
  - 성공 1건당 비용이 A의 **3배 이하**다. 이것이 사전에 정한 허용 증분 비용이다. 근거는 v1 A 실패 2회가 사람 재작업을 요구했다는 점이고, 사람 시간 측정(#410 파일럿)이 나오면 이 배수를 그 식(ΔC ≤ 0.5 × ΔA_h × w)으로 바꾼다.
- **비용 목적(v2 규칙 유지):** 비열등 ∧ 무결성 0 ∧ 비용 우월이면 "더 싼 대안"으로 기록한다.
- **B 대 V:** B가 V보다 S·거짓 완료 모두 나쁘지 않으면서 성공 1건당 비용이 V의 1.5배 이하일 때만 "고정 절차의 추가 이득 신호"로 기록한다. 아니면 "고정 절차는 V 대비 이득 없음"이다.
- n=3에서는 어떤 결과도 확정이 아니다. 신호가 나온 arm만 다음 사이클에서 n을 늘린다.

## 개정 v3.2 (2026-10-25, run 시작 전): 가설 H1·H2를 둘 다 잰다

사용자의 출발 가설은 이렇다. "모델은 계속 좋아지고, 프롬프트·스킬·workflow는 점점 필요 없어진다." 이를 둘로 나눠 잰다.

| | 가설 | 실험 |
|---|---|---|
| **H1 짧은 개발** | 단일 과제(수십 분)에서는 하네스가 품질을 올리지 못하고 비용만 늘린다 | 사이클 3: lumi-web-v1에서 A·V·VK·B·C·R ×3 |
| **H2 긴 개발** | 길고 복잡한 개발(여러 단계, 세션이 바뀜)에서도 H1이 성립한다 | 체인: 같은 arm이 자기 결과 위에서 다음 단계를 새 세션으로 이어 간다 |

**arm 추가:** VK. V에 agent-flow 스킬을 프로젝트 스킬로 노출하고, 모델이 작업 중 스스로 부른다(superpowers식). R 메뉴에 `verify-skills`(=VK)와 `compose`(라우터가 축소판을 즉석 조립, pstack `figure-it-out`식)를 더한다.

**H2 체인:**
- **웹 체인 (2단계):**
  - 1단계는 `lumi-web`(v0) 과제다. 평가기는 lumi-web 동결본이다.
  - 2단계는 1단계 결과 위에 `lumi-web-v1` 과제 문서로 바꿔 이어 간다. 평가기는 lumi-web-v1 동결본(`32b733fd…`)이다.
  - arm은 A·V·R·C, 각 n=3이다.
- **앱 체인 (F1~F3 파일럿):** 출발점은 lumi-app-v1 기준 구현이다. 단계별 평가기를 만들고 검증한 뒤 같은 arm으로 돌린다(`lumi-app-chain/DESIGN.md`).
- **단계 성공:** S=1 ∧ complete 선언 ∧ 위반 없음 ∧ 정상 종료.
- **주 지표 L:** 첫 실패 전까지 연속 성공한 단계 수.
- **보조 지표:** 단계별 G, 회귀(앞 단계 검사 실패), 단계별 거짓 완료, 버틴 단계당 비용.
- 단계가 실패해도 다음 단계는 그 결과 위에서 계속 돌린다. 실패 뒤의 회복도 본다. 다만 L은 첫 실패에서 끊는다.

**H2 판정:**
- **기각 신호** (긴 개발에는 하네스가 필요하다): 단계가 진행될수록 A와 하네스 arm의 격차가 커진다. 2단계 성공·거짓 완료 격차가 1단계 격차보다 크거나, A의 L이 가장 작다.
- **지지 신호** (긴 개발에서도 필요 없다): 모든 단계에서 A가 다른 arm보다 비열등하고, 성공 1건당 비용이 가장 낮다.
- n=3이라 둘 다 신호로만 적는다. 신호가 나오면 체인 길이(v2·v3, F4~)와 n을 늘린다.

**순서:**
1. OYG Q2 탐색(S\*)
2. 사이클 3
3. 웹 체인
4. 앱 체인 평가기가 준비되는 대로 앱 체인
- 예산은 사용자 승인 범위다. 단계마다 상한을 넘으면 멈추고 보고한다.

## 개정 v3.6 (2026-10-25): 자율 진행 규칙과 종료 조건

사용자가 결론이 날 때까지 자율로 진행하라고 승인했다. 결과를 보고 규칙을 바꾸지 않도록 지금 정한다.

**진행 순서**(앞 단계가 막히면 다음 단계를 먼저 해도 된다): OYG S\* 탐색 → 사이클 3(lumi-web-v1 × {complete, underspec} × A·V·VK·B·C·R(+S\*) × 3) → H2-① 웹 체인(v0→v1 × A·V·R·C × 3) → 앱 체인 F1–F3 → H2-② 웹 L·앱 L 파일럿(A·V·C × 2).

**자율로 해도 되는 것:**
- 과제·평가기 결함 수정. 기준 구현 실패, 검사가 PRD보다 엄격한 경우가 해당한다. 고친 뒤에는 그 평가기로 낸 기존 점수를 모두 다시 채점하고 평가기 sha를 기록한다.
- harness 결함 수정. 고친 커밋으로 고정본을 새로 만들고, 그 전 run은 "탐색"으로만 적는다.
- arm 개선(autoresearch). 판정에 쓰는 run과 섞지 않는다. 개선안은 새 이름의 arm으로 사전 등록한 뒤 별도 n=3으로 잰다.
- 신호가 애매할 때 n 늘리기. 한 비교당 최대 n=6.
